# Up and Down

Browser game for kids (React + TypeScript + Vite, tests with Vitest). The build brief is in `prompt.md`; global working agreements are in `~/.claude/CLAUDE.md`.

## Commands

- `pnpm dev` — dev server on :5173
- `pnpm test` — Vitest (jsdom); `pnpm lint` — oxlint; `pnpm build` — `tsc -b` + Vite build
- Node is pinned via Volta; use pnpm. Run test, lint and build before declaring work done.

## Worktrees

Work in a git worktree, one per session or task, not in the main checkout. Several sessions share this repo, and working in the same tree has mixed one session's half-finished files into another's commits and broken everyone's test runs. Make the worktree with `git worktree add ../up-and-down-<task> -b <task>`, run `pnpm install` in it, commit there, then merge to `main` and ship from the main checkout. Remove it when merged (`git worktree remove`). Never commit with `git add -A` in a tree another session might be using: add your own paths.

## Deploying

`pnpm ship` pushes `main` and starts the GitHub Pages workflow by hand. Pushes alone have not been triggering the workflow in this repo (cause not found), so use this until that is fixed. Site: https://run3wide.github.io/up-and-down/

## Structure

Two games, each its own bounded context, picked from the splash screen. After a round each returns to the splash (`onExit`).

- `src/up-and-down/` — Daniel's game. `domain/` is pure and framework-free: `ball` physics, `catching` verdicts, `difficulty` ramp, and the `Game` aggregate (score, lives, pause). `application/GameSession` turns held keys into movement and clamps frame time. `ui/` is the React adapter.
- `src/lemon-volcano/` — Moses's game: a strawberry throws lemons into a volcano. `domain/lemon` (fixed-power projectile; `craterAt` places each crater where a real throw lands so it's always scoreable), `domain/volcanoGame` (`VolcanoGame` aggregate: aim, toss, 8 lemons per round), `application/VolcanoSession`, `application/SoundPlayer` (port; `infrastructure/` has the Web Audio adapter that synthesises the eruption, `eruptionSound.ts` is renderable offline), `ui/` (SVG court drawn in world units). CSS classes are prefixed `lemon-volcano` because all CSS is global (the splash scene already owns `.volcano`).
- `src/dino-race/` — Daniel's racing game: steer a car down a road to the finish line, dodging cones and rocks and collecting chocolate chip cookies. `domain/course` builds the whole race up front from the injected random source (always leaves a gap to drive through); `domain/mathQuestions` + `domain/quiz` (the "brain break": five like-things maths questions in a row once the countdown ends, then the race runs uninterrupted; answers always keep their unit, e.g. 3x vs 3 vs 3y; pictures first, then letters, then mixed sums; `Quiz` is a port injected into `RaceGame`), `domain/raceGame` (`RaceGame` takes the course and an optional quiz, so tests hand-build courses; countdown, speed ramp, crashes, invulnerability, finish), `application/RaceSession`, `ui/` (HTML sprites on a square stage; the road and centre line scroll via a CSS variable and `cqh` units).
- `src/little-chef/` — Vanessa's game: an order comes in (pizza, burger, salad, fruit salad, sundae, smoothie) and you tap the ingredients that belong on that dish from a shelf that also holds ones that don't. Turn-based, so no `application/` layer or animation loop. `domain/recipes` (each `Recipe` has a `flavour`, savoury or sweet; the wrong ingredients on the shelf come from the other flavour so they are never arguable), `domain/kitchenGame` (`KitchenGame` aggregate: shelf, picks, 3 lives, dishes cooked; the shelf fills up as dishes are cooked), `ui/` (HTML buttons and a plate).
- `src/match-up/` — Daniel's memory game: flip face-down cards and keep the two that are the same *kind* (two fruits, two animals, two numbers…). `domain/kinds` (each `Kind` has a spoken `plural`, e.g. "Both are fruits!"; every item name is unique), `domain/matchGame` (`MatchGame` aggregate: deal, flip, 5 hearts, a miss costs one and a cleared board gives one back, boards are always full rows of four: 4x2, then 4x3, then a 4x4 square, which is easier for kids than a ragged shape). No timers: a missed pair stays showing until the next flip, and a cleared board waits for `nextBoard()`. Score is boards cleared. `ui/` (HTML buttons on a grid).
- `src/cookie-maze/` — Pac-Man-style maze (original art and rules, no baddies): a T-Rex eats every cookie in each maze before its clock runs out. One press = one step (a young player couldn't react to a dino that keeps walking). Running out of time costs one of 3 tries per maze, with a light "better luck next time"; after the last the player returns to the splash. `domain/maze` (`Maze.fromRows` drawing: `#` wall, `S` start, `*` super star, anything else a cookie; rejects unreachable cookies and stars), `domain/levels` (`MAZE_LEVELS`: each maze with its own time limit), `domain/mazeGame` (`MazeGame` aggregate for one maze: step, clock, lives, `tryAgain`; a super star eats the cookies within `BLAST_RADIUS` and gives `STAR_BONUS_SECONDS` back, score = cookies x 10 + seconds left; the clock starts at the first successful step), `domain/mazeRun` (`MazeRun`: the mazes in order, lives refill per maze, score adds up), `application/MazeSession`, `ui/` (SVG walls, cookies and stars in cell units, HTML dino and firework bursts positioned in percentages; bursts are CSS-only and calm under `prefers-reduced-motion`). The splash card is credited to Daniel.
- `src/tic-tac-toe/` — Daniel's noughts and crosses: the player is X and goes first, the computer is O and picks any empty square (deliberately easy to beat). `domain/ticTacToeGame` (`TicTacToeGame` aggregate: play, win/lose/draw, wins kept across rounds, `playAgain`), `ui/` (HTML buttons on a 3x3 grid). A win brings out a cheering T-Rex and plays the `winner` sound: a CC0 "Winner" clip played slowed down for a deep voice (credited in `CREDITS.md`).
- `src/spelling-bee/` — Daniel's spelling game: pick a level (easy 3–5 letters, medium 6–7, hard 8–10 such as WATERMELON and STRAWBERRY), then a picture (animal, food…) with a blank for each letter, and the A–Z alphabet to drag letters from. A right letter stays; a wrong one does a "nuh-uh" shake and goes back, costing nothing (no lives). Letters can also be tapped (pick, then tap a blank) or typed. `domain/words` (picture + spelling; `LEVELS` by `Difficulty`, `WORDS` is the easy level), `domain/spellingGame` (`SpellingGame` aggregate: place a letter in a blank, short words first and longer as the deck goes on, `nextWord()` after a word is spelled; no timers). Score is words spelled, with a best score for each level (`App` takes `spellingBestScores` apart from `bestScores`); words over seven letters wrap onto two even rows. `ui/` has `SpellingScreen` (the level picker) and `SpellingRound`. An animal's word makes its sound when spelled (a `sound` on the `Word`; mute button in the frame). `ui/` (HTML buttons; dragging uses pointer events, so touch works).
- `src/dino-dig/` — Moses's fossil game: brush dirt off a 6x5 dig site to uncover a dinosaur's bones (an empty cell shows dots for how many bones are in the cells around it), then put them back together on the skeleton stage. A wrong spot is a "nuh-uh" and the bone goes back, costing nothing; bones can be dragged (pointer events) or tapped. `domain/dinosaurs` (T-Rex, Triceratops, Stegosaurus, Brachiosaurus; each `Bone` has a `kind` and a box on a 100x60 stage), `domain/digGame` (`DigGame` aggregate: brush, place, `nextDig()`, fewer-bones dinosaurs first; no timers or lives; score is dinosaurs built). `application/CollectionStore` (port) is the museum of dinosaurs built so far, kept on the device (`infrastructure/` has the localStorage and in-memory adapters); building one roars (shared `roar`, mute button in the frame). `ui/` (HTML buttons; `BoneArt` draws each bone kind in a unit box that stretches to its slot).
- `src/colouring/` — Moses's colouring book: pick a picture (T-Rex, volcano, vehicles, animals, a hamburger, the sun, moon and all the planets, and space rockets; 33 in all), pick a colour, tap a part to fill it; every part starts blank, and each picture has 20+ parts (background, sun, clouds, spots…) so there is plenty to be creative with. There is also a Free draw pad: a blank square, 12 colours, three brush sizes, undo and clear; a drag (touch, mouse) draws a smooth round-capped line, a tap a dot, and with the keyboard the arrow keys draw and space lifts the pen. No scores, lives, timers or sound. `domain/templates` (`Template` of named `Region`s drawn as SVG paths in a 100x100 box, built with `shapes` (`band` stripes a planet); `lines` are uncoloured details), `domain/colours`, `domain/picture` (`Picture` aggregate: fill, undo, clear, finished once every part has a colour), `domain/drawing` (`Drawing` aggregate for the free pad: strokes of points kept on the page, rounded and de-duplicated). `application/GalleryStore` and `SketchStore` (ports) keep each picture, and the one free drawing, as the child left them, on the device (`infrastructure/` has the localStorage and in-memory adapters). Pointer events draw, so touch works; the pad sets `touch-action: none` so drawing never scrolls the page. `ui/` (`PictureArt` is an inline SVG whose parts are keyboard-focusable buttons; the same component draws the shelf thumbnails). It is the one game without a best score, so `App` types `bestScores` without it.
- `src/brick-builder/` — Moses's block game: drag bricks (1–4 studs wide, in colours) from the tray onto a 12-stud plate and they snap to the nearest stud and fall until they rest on the plate or another brick; tap a brick to take it off. Seen from the front, so bricks are one stud deep. No scores, lives or timers, and nothing is saved. Free build, or pick a picture to build (`domain/blueprint`: `Blueprint` of `Piece`s, shown as faint guides on the plate; a piece counts when a brick of its width is in its spot, colour is free; House, Rocket, Truck, each checked by a test that it can really be built). Landing, taking off and finishing a picture have sounds (`brickSnap`, `brickPop`, `builtIt`: synthesised in `shared/sound/brickSounds.ts`, mute button in the bar). `domain/bricks` (`BRICK_KINDS`), `domain/baseplate` (`Baseplate` aggregate: `drop`, `landingLayer`, `remove` (bricks above fall and settle again, so nothing ever floats), `clear`; `snapColumn` turns a pointer position into a column), `ui/` (HTML buttons; dragging uses pointer events, or tap a brick and then a column, which also works from the keyboard). Like Colouring it has no best score, so `App` types `bestScores` without it.
- `src/put-it-in-the-bucket/` — Moses's sorting game: pick a level, then an item pops up at the top and you drag it to the bucket it belongs in. Easy: a dog (animals), a strawberry (fruit) or a truck (vehicles). Medium: mammals, fish or birds. Hard: adds insects and the catches that look like another kind (a whale, dolphin, seal and bat are mammals; a penguin is a bird). A wrong bucket is a "nuh-uh" and the item stays for another go, costing nothing; no lives, timers or sound. Items can be dragged (pointer events) or tapped, then tap a bucket. `domain/items` (`LEVELS` by `Difficulty`, each a set of buckets and items; `BUCKETS`, `ITEMS` are the easy level; each `Item` belongs to one `Bucket`, every name and picture unique in a level), `domain/bucketGame` (`BucketGame` aggregate: `drop`, a shuffled deck that never repeats the item just sorted; score is items sorted). Each level keeps its own best score, so `App` takes `bucketBestScores` apart from `bestScores`. `ui/` (`BucketScreen` is the level picker, `BucketRound` the play; HTML buttons). Leave via Home to change level.
- `src/treasure-map/` — pirate treasure hunt (no byline on the splash card yet; the game was chosen rather than designed by a child): a parrot flies one spot at a time over an 8x6 island map and follows clues like "3 steps east, then 2 steps north" from the ship to a landmark (palm tree, hut, lighthouse…), whose next clue leads on, until the last clue ends at the buried treasure. Counting wrong costs nothing, "Back to the start of this clue" is free, no lives or timers; score is treasures found, and hunts grow from 2 clues to 4. `domain/island` (`Spot`, `Compass`, north is up), `domain/hunt` (`buildHunt` lays the whole map out from the injected random source: every clue is a row leg then a column leg of 2–7 spots, a landmark ends each clue but the last, the rest are decoys), `domain/treasureGame` (`TreasureGame` takes a `newHunt` factory so tests hand-build maps; `cluesForHunt`), `ui/` (`TreasureMap` is an SVG in spot units with a compass round the edge; HTML arrow buttons, arrow keys and WASD; mute and pause in the frame; reuses the `brickSnap` and `builtIt` sounds).
- `src/dino-clues/` — a find-the-clues mystery with an original dino detective (deliberately not branded after any TV show; no byline on the splash card yet): a question ("What pet does Dino want?") and 8 hiding places (tree, rock, bucket…); three of them, picked at random, hold a clue and the rest say "nothing here". Find all 3 clues, then pick from 3 choices; a wrong one is a "nuh-uh" and costs nothing, a right one cheers (`victoryRoar`), scores and brings the next mystery. No lives or timers; score is mysteries solved. `domain/mysteries` (hand-written `MYSTERIES` across snacks, pets, places and toys: every clue is true of the answer and every other choice breaks at least one, so nothing is arguable; `HIDING_PLACES`), `domain/dinoCluesGame` (`DinoCluesGame` aggregate: `look`, `guess`, `nextMystery`, a shuffled deck that never repeats the mystery just solved), `ui/` (HTML buttons; a clue notebook of three slots). Mute and pause in the frame.
- `src/cake-bakery/` — Thomas's cake game: build a cake in four steps (shape: dinosaur, strawberry, race car, fish, shark, tiger; flavour; frosting; topping), and each step is unlocked by a like-things maths question (the dino-race `MathQuestion`/`Quiz` port, reused). `domain/cakeQuestions` (`cakeQuiz`: fruit or shapes at first, then letters, then four-term sums like 1x + 2y + 3x + 1y; the dino-race `sameThing`/`mixedThings` builders are exported for it), `domain/ingredients` (`CHOICES` by `Step`; toppings are look-alike treats, never real brands), `domain/bakeGame` (`BakeGame` aggregate: `answer`, `choose`, `nextCake()`; a wrong answer costs nothing; score is cakes baked). No lives, timers or sound. `ui/` (HTML buttons; `CakeArt` is an SVG of the cake from above: each shape has its own outline, the sponge shows round the edge in the flavour colour, the frosting sits on top, features like eyes and stripes keep their own colours, and toppings are drawn at set spots; keyed by the ingredient's name).
- `src/shared/theme/` — light and dark mode. `theme` (`Theme`, `ThemeStore` port, `chooseTheme`: the child's last pick wins, else the device's setting), `LocalStorageThemeStore`/`InMemoryThemeStore`, `ThemeContext` (`useThemeController` keeps `<html data-theme>` in step), `ThemeToggle` (moon/sun button on the picker and in the frame bar; absent where no theme is wired up). `dark.css` holds the night variables (`--ink`, `--surface`, `--sky-*`…) and each game's night backdrop; stylesheets use `var(--surface)` rather than `#fff`, and line art on white paper uses `--paper-ink` so it stays dark. Check a new game in dark mode: screenshot it with the theme forced.
- `src/shared/frame/` — `GameFrame`, the bar around every game (`App` wraps each screen in it): Home on the left (asks "Leave game?" first, and pauses the game while the card is up), the game's name, then the mute and pause buttons. A game plugs those in by rendering `<FrameControls sound={…} pause={…} />` (a portal into the bar), so mute and pause sit and look the same everywhere; games without sound or pause leave that prop out. Screen tests render through `test-support/inFrame`. Games no longer have their own Home button; the pause card's "Main menu" and game-over "Back to games" remain.
- `src/shared/` — best-score port + adapters (`LocalStorageBestScoreStore(key)`, in-memory), `useAnimationFrame`, shared overlays/HUD/touch-control CSS. `sound/` holds the `SoundPlayer` port (`play('eruption' | 'roar' | 'victoryRoar')`) and its Web Audio adapter (the eruption is synthesised; the roars and Spelling Bee's animal sounds (`animals/`, real CC0 or public-domain recordings; animals without a good recording stay silent rather than get a synthesised one) are small clips bundled as data URLs, credited in `CREDITS.md`); the games with a T-Rex (Up and Down, Dino Race, Cookie Maze) roar on a catch and the race start, and do the victory roar at the race finish and a won maze, each with a mute button in the frame.
- `src/splash/` — game picker, Up and Down logo. `src/art/` — shared inline-SVG art.
- `src/routing/` — each game has its own address (`<base>up-and-down`, `<base>lemon-volcano`; the bare base is the picker). Pure path functions plus a `useRoute` history hook. The base is `/` in dev and `/up-and-down/` in production (`vite.config.ts`); the build copies `index.html` to `404.html` so GitHub Pages serves the app for direct links.
- `src/App.tsx` picks the screen from the route; `src/main.tsx` is the composition root (`Math.random`, one localStorage key per game).
- Domain code is deterministic: randomness is injected, no clock or DOM.

## Conventions

- TDD; test the domain without React. UI tests drive the loop with Vitest fake timers (fake `requestAnimationFrame`) and use `fireEvent` — `userEvent` hangs under fake timers.
- Usability and safety suites: `src/usability.test.tsx` opens every game from the picker (one case set per game; `Record<GameId, …>` forces a new game to be added there), `src/childSafety.test.ts` guards the kid-safety and privacy rules. jsdom has no layout, so `test-support/loadStyles` puts the real CSS on the page to check the cascade (scrolling, grid sizing), but whether a screen *fits* needs a real browser: screenshot it at true phone width (headless Chrome clamps `--window-size` to ~500px, so use a 390px-wide iframe) in portrait and landscape.
- tsconfig has `erasableSyntaxOnly`: no constructor parameter properties or enums.
- Domain-driven names: code uses the game's own words (lemon, crater, brain break), not generic ones.

## Safe for kids

The players are young children, and some of the builders are too (the games are credited to the kids who designed them).

- Soft by default: gentle sounds and effects, no scary failure states, no flashing or strobing, respect `prefers-reduced-motion`. Losing is "try again", never punishment.
- Keep sound moderate and never start it before a tap or key press (browsers require this anyway).
- No ads, links out, chat, user-generated text, accounts, in-app purchases or anything that leads a child off the page.
- Content stays kind and age-appropriate: no violence, no real-world brands, no scary imagery.
- Touch and keyboard must both work; targets are big, and text is short and readable.
- Maths and other learning content stays encouraging: wrong answers get another go, not a penalty.

## Public repo: keep private info out

The repo and the deployed site are public (GitHub Pages), and so is the full git history. Anything committed is visible forever.

- No network calls, analytics, tracking, cookies or third-party scripts, fonts or CDNs. Everything is bundled. The only storage is `localStorage` for best scores (and Dino Dig's museum, Colouring's pictures and free drawing, and the light or dark mode pick), on the device.
- Never commit secrets, tokens, `.env` files, personal emails, phone numbers, addresses, school names, photos of the kids, or real voices/recordings.
- Credit kids by **first name only** in anything new (UI, README, tests, docs, commit messages, code comments). No surnames, ages or birthdays, and no locations or schedules.
- Commit with a no-reply identity, not a personal address or machine hostname (`git config user.email <id>+<user>@users.noreply.github.com`).
- Keep `prompt.md`, notes and test fixtures free of anything you would not put on the site itself.
- Before pushing, scan the diff for names, emails and paths: `git diff --cached | grep -inE "@|/Users/|token|secret|key"`.
- Don't paste real user data, screenshots with personal details, or absolute local paths into the repo.
